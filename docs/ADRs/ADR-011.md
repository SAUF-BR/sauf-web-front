# Estilização com CSS Modules em vez de styled-components

- Status: aceito
- Decisores: Leonardo
- Data: 2026-09-16
- História Técnica: ADR-009 da planilha "SAUF - ADRs" do frontend web (Vite + React SPA)

## Contexto e Declaração do Problema

O SPA do SAUF precisa de uma abordagem de estilização consistente entre telas. Entre as opções que fazem sentido para o perfil e o cronograma do time — CSS Modules e styled-components (CSS-in-JS) — qual adotar?

## Fatores da Decisão

- Familiaridade prévia do time com CSS tradicional
- Tempo hábil disponível no cronograma do projeto para aprender uma nova ferramenta
- Custo de performance em runtime
- Consistência de estilos entre telas

## Opções Consideradas

- CSS Modules
- styled-components (CSS-in-JS)

## Resultado da Decisão

Opção escolhida: "CSS Modules", porque o time já tem familiaridade com CSS tradicional, o que aproveita melhor o tempo hábil disponível no cronograma do projeto, sem precisar dedicar tempo a aprender uma nova sintaxe ou uma biblioteca de CSS-in-JS.

### Consequências Positivas

- Curva de aprendizado praticamente nula, já que o time já conhece CSS tradicional
- Melhor aproveitamento do tempo hábil do cronograma do projeto
- Escopo automático de classes por arquivo, sem dependência de runtime

### Consequências Negativas

- Exige alternar constantemente entre o arquivo `.tsx` e o `.module.css` correspondente
- Não centraliza tokens de design (cores, espaçamentos) automaticamente como uma solução com configuração central faria; a consistência visual depende de disciplina do time (ex.: variáveis CSS compartilhadas)

## Prós e Contras das Opções

### CSS Modules

Um arquivo `.module.css` por componente, com escopo automático de classes, usando a sintaxe de CSS que o time já conhece.

- Bom, porque o time já tem familiaridade com a sintaxe, sem curva de aprendizado
- Bom, porque tem escopo automático por arquivo, sem dependência de runtime
- Ruim, porque exige alternar entre o arquivo `.tsx` e o `.module.css` correspondente a cada ajuste de estilo

### styled-components (CSS-in-JS)

Estilos escritos dentro do próprio componente usando template literals.

- Bom, porque o estilo fica colocado junto ao componente que o usa, sem arquivo separado
- Ruim, porque exige que o time aprenda uma nova biblioteca e sintaxe, consumindo tempo hábil do cronograma
- Ruim, porque tem custo de performance em runtime pela geração dinâmica de classes
