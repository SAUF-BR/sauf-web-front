# ADR-001 - Vite+React (SPA) em vez de Next.js

- Status: aceito
- Decisores: Carlos Eduardo Souza Favarão
- Data: 2026-09-16

## Contexto e Declaração do Problema

O projeto da Escola de TI precisava de um frontend funcional e leve, capaz de atender os propósitos da ideia como um todo utilizando o backend Java como provedor dos dados. Um ambiente Next.js seria redundante, pois o sistema monolítico (com front e back no mesmo projeto) teria pouca utilidade em um contexto que já conta com uma API robusta em Spring Boot.

Qual abordagem de frontend adotar para consumir a API Spring Boot sem duplicar responsabilidades já cobertas pelo backend?

## Fatores da Decisão

- Experiência de uso e fluidez: ao decidir por uma SPA em Vite, optamos por priorizar uma navegação fluida, tratando todas as ações na mesma janela, sem criar confusão para o usuário;
- Desenvolvimento e escalabilidade: um ambiente React possui inúmeras vantagens relacionadas à disponibilidade de bibliotecas e conteúdo, facilitando a evolução do projeto;
- Separação de responsabilidades: o backend em Spring Boot já é o provedor de dados e regras de negócio, então o frontend deve se concentrar apenas na interface;
- Leveza: o frontend deve ser simples de configurar e rápido de executar, sem a complexidade adicional de um framework fullstack.

## Opções Consideradas

- Opção 1: Vite + React como SPA (Single Page Application), consumindo a API Spring Boot
- Opção 2: Next.js (frontend e backend no mesmo projeto)

## Resultado da Decisão

Opção escolhida: "Opção 1 - Vite + React como SPA", porque atende ao que o projeto precisa sem redundância: o backend em Spring Boot já cumpre o papel de provedor de dados, o que torna desnecessários os recursos fullstack do Next.js, e a SPA entrega a navegação fluida e o ecossistema React desejados com um frontend leve.

### Consequências Positivas

- Navegação fluida, com todas as ações tratadas na mesma janela;
- Separação clara entre frontend (interface) e backend (dados e regras de negócio);
- Frontend leve e simples de configurar, com o Vite;
- Acesso ao amplo ecossistema de bibliotecas e conteúdo do React;
- Frontend e backend podem evoluir e ser publicados de forma independente.

### Consequências Negativas

- Sem renderização no servidor (SSR/SSG), o que pode prejudicar o SEO e o tempo de carregamento inicial;
- Roteamento, gerenciamento de estado de servidor e demais recursos que o Next.js já traz precisam ser escolhidos e configurados manualmente (ex.: [ADR-003](ADR-003.md) para estado de servidor);
- Como frontend e backend rodam em origens distintas, é necessário configurar CORS e a autenticação entre eles.

## Prós e Contras das Opções

### Opção 1 - Vite + React (SPA)

SPA em React empacotada com o Vite, que consome os dados da API Spring Boot.

- Bom, porque a navegação é fluida, sem recarregamentos de página;
- Bom, porque evita a redundância de ter um backend também no frontend, já que a API Spring Boot é robusta;
- Bom, porque o ecossistema React oferece muitas bibliotecas e conteúdo disponíveis;
- Bom, porque é leve e simples de configurar;
- Ruim, porque não possui SSR/SSG nativo, o que pode impactar o SEO e o carregamento inicial.

### Opção 2 - Next.js

Framework fullstack baseado em React, com renderização no servidor e backend integrado ao mesmo projeto.

- Bom, porque oferece SSR/SSG e otimizações de SEO prontas para uso;
- Bom, porque traz roteamento e outros recursos já integrados;
- Ruim, porque seria redundante, já que o backend está em Spring Boot e um sistema monolítico teria pouca utilidade nesse contexto;
- Ruim, porque adiciona complexidade desnecessária para um frontend que apenas consome uma API.
